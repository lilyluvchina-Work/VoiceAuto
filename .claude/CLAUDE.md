# CLAUDE 协作规则

## 文档定位

- 用途：定义本仓库 AI 协作的统一高优先级规则。
- 优先级：高于一般说明性文档，低于系统与平台强制规则。

请始终遵循以下守约：

# 项目通用规则

## 代码风格

- 使用简洁清晰的代码，避免过度设计
- 函数/变量命名使用英文，语义明确
- 添加必要注释，解释“为什么”而非“是什么”
- 所有异常描述仅使用英文
- 所有业务代码中抛出的'RuntimeException',需要指定独立的错误码和错误信息

## 响应要求

- 回答简洁，直奔主题
- 提供代码时附带简短说明
- 不确定时主动询问，不猜测

## 输出格式

- 代码块标注语言类型
- 多方案时列出优缺点供选择
- 复杂内容使用列表或表格组织
- 生成流程设计的时候绘图优先考虑采用MerMaid格式，需要尽量简洁、无交叉、布局美观。

## 沟通偏好

- 默认使用中文交流
- 回答时先给结论，再展开细节
- 涉及代码变更时，先说明影响范围

## 限制条件

- 不生成未经测试的代码
- 涉及敏感操作时提醒安全风险
- 不确定的依赖版本需确认                            |

## 项目启动与环境准备

- 首次进入项目先安装依赖：`npm install`。
- 日常开发默认启动命令：`npm run dev`。
- 如需启用豆包 TTS：
  - 复制 `.env.example` 为 `.env`。
  - 填写豆包 `AppId` 与 `AccessToken`。
  - 配置可用时优先使用豆包 TTS，失败自动回退 Web Speech API。

## 变更验证与运行

- Bug修复与功能点优化完成后，统一执行生产构建验证流程：`npm run build`。
- 构建通过后，自动启动项目进行运行验证：`npm run dev`。
- `docx/BUGFIX-RECORD.md` 与 `docx/FEATURE-OPTIMIZATION-RECORD.md` 不再重复维护“验证”段落，验证要求统一以本节为准。

## 其他守约

- 当重复执行多次异常时，最大允许错误两次即停止，且返回异常原因。
- 拓展内容前需要先询问是否拓展，优先总结，再询问后给出详细内容。

## AI 协作配置

### 上下文管理原则

- **配置驱动优先**：将隐性知识下沉到配置文件，对话专注于即时任务。
- **精简胜于详尽**：保持规则具体且高权重，避免模糊描述稀释关键信息。
- **活文档机制**：每次 AI 犯错并纠正后，立即将经验总结为具体规则追加到文档中。

### 文件结构规范

- **核心文件**：`.claude/CLAUDE.md` 存放全局背景、技术栈和核心架构约定。
- **模块化拆分**：
  - 当文件超过 200 行或规则仅针对特定目录时，拆分至 `.claude/rules/`。
  - 固定执行流程封装为 Skill，存放在 `.claude/skills/`。
- **个人配置**：个人偏好（如编辑器 quirks）放入 `CLAUDE.local.md` 并加入 `.gitignore`。

### 命名与加载

- **大小写敏感**：文件名必须严格为 `CLAUDE.md`（全大写，位于 `.claude/` 目录）。
- **加载机制**：`.claude/CLAUDE.md` 作为全局规则文件；`.claude/rules/` 与 `.claude/skills/` 按目录与场景加载。

### 迭代与维护

- **具体化规则**：用“函数不超过 40 行”替代“保持代码整洁”。
- **自我优化**：定期让 AI 审查并优化 `.claude/CLAUDE.md`，合并冗余规则。
