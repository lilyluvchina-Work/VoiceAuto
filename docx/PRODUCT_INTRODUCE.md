# VoiceAuto 产品文档

## 文档定位

- 目标读者：产品、测试、研发协作人员。
- 内容范围：产品目标、能力边界、业务流程、非功能要求与迭代方向。

## 1. 产品概述

VoiceAuto 是一个面向语音助手测试场景的前端自动化测试平台。产品提供从测试用例导入、语音参数配置、批量播放执行、自主监测到报告导出与日志分析的一体化流程，帮助测试与开发团队快速完成语音交互能力验证。

当前版本主要运行在浏览器端，支持 Web Speech API，并可通过环境变量切换为豆包 TTS 优先、Web Speech 回退的双通道语音合成策略。

在自主监测模式下，VoiceAuto 不再只依赖固定等待时间推进测试，而是通过 ADB 日志、播放器事件和外部麦克风采集共同判断：

- Speaker 是否已被唤醒。
- Speaker 是否识别到测试音频输入。
- Speaker 是否实际播放回复内容。
- 每条用例失败发生在哪个链路。

## 2. 目标用户

- 语音助手测试工程师
- 语音产品研发工程师
- 需要批量验证语音文案播放效果的产品经理

## 3. 核心价值

- 提升测试效率：批量执行语音用例，减少重复人工点击。
- 提升可追溯性：自动生成结构化测试报告，支持 Markdown、HTML、Excel 导出。
- 提升问题定位速度：提供日志导入与多维筛选分析能力。
- 提升自动判定能力：通过唤醒、输入 ASR、Speaker 响应三阶段自主监测，减少人工观察和固定等待带来的误判。
- 降低使用门槛：纯前端部署，开箱可用，无需额外后端服务。

## 4. 功能范围

### 4.1 语音测试模式

#### 4.1.1 唤醒词配置

- 配置唤醒词文本。
- 配置唤醒后延迟（wakeAfterDelay）。
- 配置唤醒间延迟（wakeIntervalDelay）。
- 支持“试听唤醒词”即时验证。

#### 4.1.2 音频配置

- 音色选择（男女声）。
- 语种/方言选择。
- 音量调节（0%~200%）。
- 播放倍速调节（0.5x~2.0x）。

#### 4.1.3 测试用例导入

- 文本导入：上传 txt，每行一条用例。
- 文件导入：支持 mp3/wav/ogg/m4a，多文件导入。
- 手动输入：可粘贴多行文本生成多条用例。
- 模块归类：导入时可指定模块（含自定义模块）。

#### 4.1.4 播放控制台

- 开始、暂停、继续、停止、重置。
- 支持循环播放次数配置（当前支持 1/2/3/5/10/20/50 次）。
- 显示当前状态、当前进度、已用时间、预计剩余时间。
- 展示当前播放内容与播放阶段（唤醒词/唤醒检测/测试音频/ASR 检测/响应检测/重启等待/延迟）。
- 支持播放序列调试日志开关，可在控制台输出真实执行序列。
- 支持按测试模块执行，并可选择测试结束后自动拉取的 Langfuse 日志环境。
- 自动拉取开启时，测试完成后会停留语音测试页 2 分钟，再跳转 Langfuse 日志页拉取所选环境日志。
- 支持自主监测配置：
  - 自主监测 Speaker 唤醒是否成功。
  - 自主监测测试音频输入和 ADB ASR 识别状态。
  - 自主监测 Speaker 响应内容，支持外部麦克风采集和 ADB VAD/TTS 日志检测。
- 键盘快捷键：
  - Enter：开始
  - Space：暂停/继续
  - Esc：停止

#### 4.1.5 自主监测能力

自主监测能力分为三段：

| 阶段 | 监测目标 | 判定依据 |
|---|---|---|
| 唤醒监测 | Speaker 是否唤醒成功 | ADB `WakeupSuccess` 日志 |
| 输入监测 | Speaker 是否识别测试音频 | ADB `asr_status=partial/final/unidentified` |
| 响应监测 | Speaker 是否实际播放回复 | 麦克风响应音频 + ADB `vad_status=start/stop` + ADB `tts_status` |

关键行为：

- 开启自主唤醒后，检测到 Speaker 唤醒成功即播放测试音频，不再等待固定唤醒后延迟。
- 开启任一自主监测后，用例之间跳过固定唤醒间隔，直接进入下一条用例的唤醒流程。
- 连续唤醒失败达到阈值后，可通过 ADB 重启 Speaker；重启恢复后等待 2 分钟再重试当前用例。
- ASR 成功与失败由 `asr_status` 标识判断，文本相似度仅用于诊断。
- Speaker 回复内容优先来自 ADB `tts_status` 提取的 `speakerResponseText`；麦克风转写仅作为辅助证据。

#### 4.1.6 测试过程记录与报告

- 统计总用例、成功数、失败数、成功率。
- 统计总耗时与平均每条耗时。
- 展示用例执行明细。
- 合并展示每条用例的唤醒链路、输入 ASR 链路、响应链路过程日志。
- 支持按链路筛选过程日志，并对重复日志进行去重。
- 区分展示：
  - 测试音频文本：测试用例目标输入。
  - 获取到的 ASR 文本：Speaker 对测试音频输入的识别结果。
  - 麦克风转写响应文本：外部麦克风采集 Speaker 回复音频后的辅助转写。
  - Speaker 播放响应文本：从 ADB `tts_status` 日志提取的实际播放内容。
- 支持复制报告、下载 txt 报告。
- 测试进行中可点击“查看报告”，且不会打断当前音频播放。
- 报告数据为空时提供明确占位提示，避免空白视图。

### 4.2 日志分析模式

- 支持任意后缀日志文件按文本导入。
- 自动解析时间、级别、模块、消息。
- 支持按文件名、导入日期筛选日志记录。
- 支持按时间区间、关键字、日志级别筛选日志条目。
- 输出统计与分析结论，辅助问题定位。
- 本地缓存日志记录（localStorage），并在容量不足时自动降级压缩保存。

### 4.3 Langfuse 日志获取模式

- 支持从 Langfuse 平台拉取 **Traces** 与 **Observations** 数据。
- 支持多环境切换，切换后自动使用对应凭据：
  - **UAT**（紫色标识）
  - **UAT-Local**（青色标识）
  - **TEST**（黄色标识）
  - **PROD**（红色标识）
- 时间范围选择器支持精确到秒的开始/结束时间配置，并提供快捷选择（15 分钟 / 1 小时 / 6 小时 / 24 小时 / 3 天 / 7 天）。
- 自动分页拉取所有数据（每页 100 条），显示实时进度。
- 支持 **暂停 / 继续 / 终止并保留** 当前已获取数据。
- 自动过滤 input、output、name 均为空的无效记录，并统计过滤数量。
- 自动关联 Traces 与 Observations 的 Session，展示匹配的 SessionID 列表。
- 支持数据预览（表格展示，悬浮查看完整字段内容，横向滑动）。
- 日志提取预览支持按 familyid / deviceid 筛选；启用筛选后，生成报告与日志提取 Excel 基于筛选结果。
- 支持导出 Excel（Traces + Observations 各一个 Sheet）与 JSON 格式下载。
- 支持基于日志提取结果生成总结报告。

### 4.4 总结报告模式

- 集中展示最新一次由 Langfuse 日志生成的总结报告。
- 基础信息与功能模块统计为只读展示，避免误改自动统计口径。
- 提测参数支持按“模型配置 / 语音识别配置”分组编辑，并可导入 `.xlsx/.xls/.csv/.txt` 参数文件。
- 报告表格以本次实际执行音频为主，未执行用例不计入本次报告。
- 报告正文采用 Markdown 表格结构，可导出 Markdown、HTML、Excel。
- Excel 报告包含汇报看板、报告概览、提测参数、功能模块统计、错误信息、重点数据和测试明细。

## 5. 关键业务流程

### 5.1 语音测试流程

1. 用户配置唤醒词与语音参数。
2. 用户导入或手动添加测试用例。
3. 用户启动测试。
4. 系统播放唤醒词，并通过 ADB 日志检测 Speaker 是否唤醒成功。
5. 唤醒成功后立即播放测试音频，并通过 ADB ASR 状态检测 Speaker 是否识别输入。
6. 测试音频播放完成后立即进入响应检测窗口，通过麦克风确认 Speaker 是否实际发声，并通过 ADB VAD/TTS 日志获取 Speaker 实际播放回复文本。
7. 系统实时记录每条用例执行结果和每一步过程日志。
8. 测试停止或完成后生成过程报告；若开启自动拉取，则停留 2 分钟后跳转 Langfuse 并拉取所选环境日志。

### 5.2 日志分析流程

1. 用户导入日志文件。
2. 系统解析并生成结构化日志条目。
3. 用户按条件筛选日志。
4. 系统输出统计结果与重点异常信息。

### 5.3 Langfuse 日志获取流程

1. 用户选择目标环境（UAT / UAT-Local / TEST / PROD）。
2. 用户选择时间范围（精确到秒）。
3. 用户点击"获取日志"，系统分页并发拉取 Traces 和 Observations。
4. 用户可随时暂停、继续或终止（终止后保留已获取数据）。
5. 获取完成后系统自动过滤空记录，关联 Session，展示统计卡片。
6. 用户可按 familyid / deviceid 筛选日志提取结果。
7. 用户预览数据、下载 Excel / JSON，或生成总结报告。

## 6. 数据与状态（前端）

- 全局状态通过 React Context + useReducer 管理。
- 持久化内容：唤醒词配置、默认语音配置、测试选项（循环次数/调试开关/自动拉取环境/模块筛选/自主监测配置）、测试用例列表、日志记录（部分压缩）。
- 临时运行状态：播放状态、总队列进度、当前列表索引、报告中间数据、过程日志。
- 过程日志：按唤醒链路、输入链路、响应链路记录，并在写入时执行内容指纹去重。
- 响应音频：浏览器运行时生成 `responseAudioUrl` 用于页面回放，不作为长期持久化文件保存。

## 7. 技术方案

- 前端框架：React 18
- 构建工具：Vite 5
- 样式：Tailwind CSS
- 语音合成：
  - Web Speech API（默认）
  - 豆包 TTS（可选，需环境变量）
- 自主监测：
  - ADB Bridge：本地 Node 服务，负责调用 `adb logcat`、ADB 重启和设备恢复检测。
  - 唤醒检测：监听 `WakeupSuccess` 等唤醒成功日志。
  - 输入 ASR 检测：监听 `asr_status=partial/final/unidentified`。
  - 响应检测：监听 `vad_status=start/stop` 和 `tts_status`，并通过外部麦克风采集 Speaker 响应音频。
  - 麦克风响应 ASR：浏览器 Web Speech Recognition，用作辅助转写。
- 报告导出：浏览器 Blob 下载 txt / Markdown / HTML，xlsx 导出 Excel
- Langfuse 日志导出：xlsx 库导出 Excel，Blob 下载 JSON
- Langfuse 接入：Vite Dev Proxy 转发（绕过 CORS），Basic Auth 鉴权

## 8. 环境配置

可选启用豆包 TTS，主要变量如下：

- VITE_TTS_PROVIDER
- VITE_DOUBAO_TTS_URL
- VITE_DOUBAO_APP_ID
- VITE_DOUBAO_ACCESS_TOKEN
- VITE_DOUBAO_CLUSTER
- VITE_DOUBAO_VOICE_TYPE
- VITE_DOUBAO_UID

当 provider 为 doubao 且配置可用时优先豆包；失败自动回退 Web Speech。

自主监测依赖本机 ADB Bridge：

- 默认地址：`http://127.0.0.1:17321`
- 启动方式：`npm run adb:bridge`
- Speaker 设备需可通过 ADB 访问。
- 若配置了固定 ADB Device ID，检测、重启和日志监听都会使用该设备。
- 修改 ADB Bridge 脚本后，需要重启 ADB Bridge 服务才能生效。

## 9. 非功能要求

- 可用性：界面操作反馈明确，关键操作具备错误提示。
- 兼容性：优先支持现代浏览器（Chrome/Edge/Firefox/Safari 新版本）。
- 性能：常规测试与日志分析在前端本地处理，避免网络依赖。
- 安全性：不上传用户日志与测试文本到平台后端（除用户主动配置外部 TTS 服务请求）。
- 可观测性：自主监测全过程写入测试过程记录，便于定位唤醒、输入和响应链路问题。

## 10. 已知限制

- Web Speech 语音质量与可用音色受浏览器与系统环境影响。
- 麦克风响应 ASR 依赖浏览器 Web Speech Recognition，部分浏览器可能不可用；此能力仅作为辅助转写。
- Speaker 实际播放回复文本依赖 ADB `tts_status` 日志中包含可提取文本。
- 响应开始/结束依赖 ADB `vad_status=start/stop` 日志；若设备不输出该日志，响应链路只能依赖麦克风采集作为辅助判断。
- 自主监测依赖 ADB 连接稳定性；设备重启、offline、unauthorized 或无线 ADB IP 变化会影响检测。
- 浏览器自动播放策略可能影响首次播放体验。
- 大体积日志文件受浏览器内存和 localStorage 容量限制。
- 当前暂未提供 PDF 报告导出。
- 当循环次数较高（例如 50 次）且用例较多时，整体执行时间会明显增加。
- Langfuse 代理仅在 Vite 开发服务器（`npm run dev`）下生效；生产构建需额外配置反向代理。
- Langfuse 大时间跨度查询（如 7 天）可能需要较长拉取时间，受网络和数据量影响。

## 11. 迭代建议

- 增加测试任务模板与批量参数预设。
- 增加测试结果对比（历史版本成功率变化趋势）。
- 增加报告格式扩展（JSON/CSV/PDF）。
- 增加日志异常规则引擎（可配置告警规则）。
- 增加多环境配置管理（开发/测试/生产）。
- 增加响应内容语义校验能力，对 `speakerResponseText` 做意图或预期答案匹配。
- 增加响应音频长期归档能力，支持按批次下载录音文件。

## 12. 验收标准

- 可完成唤醒词配置、语音参数配置与测试用例导入。
- 可稳定执行完整语音测试流程并展示进度。
- 可开启自主监测并完成唤醒、输入 ASR、Speaker 响应三阶段判定。
- 可在测试过程记录中区分展示测试音频文本、输入 ASR 文本、麦克风转写响应文本和 Speaker 播放响应文本。
- 可生成并导出测试报告。
- 可导入日志并执行筛选分析。
- 刷新页面后关键配置与用例可恢复。
