# 项目周报（2026-06-01 ~ 2026-06-06）

## 1. 本周结论

- 本周核心工作聚焦在“Speaker 自主监测链路稳定性”和“Speaker TTS 播报音频录制”。
- 已完成项目启动环境自检、ADB/logcat 监听链路恢复、ASR 日志文本提取、TTS 文本与音频记录、测试过程详情展示和统计汇总。
- 针对“唤醒成功后测试音频未播放”“TTS 录音偶发为空或截断”“隔夜启动监听异常”等问题已完成修复和构建验证。

## 2. 本周项目更新

### 2.1 启动自检与监听链路恢复

- `npm run dev` 接入启动自检，优先检查 ADB bridge、Speaker 设备、logcat 可读性和前端端口状态。
- ADB bridge 支持 `/api/adb/devices`、`/api/adb/health`、`/api/adb/recover`。
- 启动异常会写入 `logs/startup-error.log`，并同步记录解决方案。
- 自检结果写入 `logs/startup-check.log`，便于复盘启动失败原因。
- 播放控制台新增 Speaker 监听链路自检面板，支持重新自检和一键恢复。

### 2.2 Speaker TTS 录音方案落地

- Speaker 响应录音升级为连续 PCM 采样并输出 WAV 文件，提升录制稳定性。
- 根据 TTS 文本长度动态估算播报时长，增加最短保护时长，避免长回复被静音判断提前截断。
- 长文本回复使用更长静音结束阈值，并增加最大录制时长兜底。
- 下一轮唤醒延后到 Speaker 播报结束并冷却后再执行，减少尾音重叠和打断。
- 测试结果中同时保留 Speaker 播放的 TTS 文本和录音文件。

### 2.3 ASR 与响应日志监听增强

- ASR 文本支持从 `GoogleLiveResponseBean` 的 `asr_status/input_text` 日志中提取。
- 响应链路支持通过 ADB `vad_status=start/stop` 判断 Speaker 播报开始和结束。
- 响应文本优先从 Speaker 端 `tts_status` 日志提取，麦克风 ASR 作为诊断参考。

### 2.4 测试过程记录与报告增强

- 测试过程记录支持点击展开详情，展示唤醒、测试音频、ASR、TTS 全链路过程。
- 页面汇总展示唤醒成功/失败、ASR 成功/失败、TTS 成功/失败。
- 详情中展示 Speaker 播报录音播放器、下载入口、录音 ASR、文本相似度、录音时长、采样率、结束原因和疑似截断标记。
- JSON/CSV/文本报告同步输出 TTS 文本、TTS 音频和录制诊断字段。

### 2.5 代码架构与性能优化

- 抽取 `src/utils/testStatus.js`，统一过程记录和报告导出的状态判断口径。
- `useTestRunner` 抽取响应运行配置归一化，减少重复默认值和类型转换逻辑。
- `responseMonitorService` 将录音窗口、缓存时长、阈值和保护时长计算移出高频音频回调，降低录音过程重复计算。
- 关键链路补充简短注释，提升后续维护可读性。
