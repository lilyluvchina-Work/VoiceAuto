# 音箱黑盒语音测试实现方案

## 一、实现目标

基于现有语音自动化测试工具，新增“音箱黑盒语音测试”模块，支持以下设备：

| 设备类型 | 唤醒词 | 测试音频语言 | 唤醒确认方式 |
|---|---|---|---|
| 小米音箱 | 小爱同学 | 中文 | 检测唤醒语音或提示音 |
| 百度音箱 | 小度小度 | 中文 | 检测唤醒语音或提示音 |
| Google 音箱 | Hey Google | 英文 | 检测唤醒提示音，测试前开启该设置 |

不依赖设备实时日志。一次只测试一台设备，通过电脑播放声音、录制音箱发声，完成唤醒判定、回复判定、响应耗时统计和独立 HTML 报告导出。

硬件连接约定：电脑外接扬声器负责播放，外接麦克风或带麦克风的声卡负责录音。普通扬声器无法完成录音。

Google 官方列出的唤醒词为“Hey Google”或“OK Google”，可开启唤醒提示音：[Google 官方说明](https://support.google.com/googlehome/answer/7410241?hl=en)。本方案默认使用“Hey Google”。

## 二、开发前检查

先阅读现有工程，定位以下能力：

- 测试音频导入及列表管理。
- 音频输出设备选择与播放。
- 音频输入设备选择与录制。
- 测试任务启动、停止、重试和进度显示。
- 配置保存及文件导出。

复用适用的基础能力。如果尚不支持同时播放和录音，补充全双工音频功能。

新增独立的测试调度、声音判定、结果数据结构和报告生成器。不复用现有工具的报告模板或报告生成逻辑。

遵循现有技术栈，不为了新增功能重写整个工程。

## 三、测试流程

```text
初始化音频设备并持续录音
    ↓
采集环境底噪
    ↓
播放唤醒词
    ↓
等待唤醒语音或提示音
    ├─ 超时 → 保存本轮结果和录音 → 按规则重试
    ↓
等待唤醒回应结束
    ↓
播放测试音频
    ↓
等待设备语音回复
    ├─ 超时 → 保存本轮结果和录音 → 按规则重试
    ↓
确定回复起点并计算响应耗时
    ↓
继续录制至回复结束
    ↓
保存本轮结果和录音
    ↓
执行下一条测试
    ↓
生成独立 HTML 报告
```

每次重试都必须重新执行“唤醒 → 等待回应 → 播放测试音频 → 监听回复”，不能只重复播放测试音频。

### 重试规则

将“超时重试 5 次”定义为：

- 首次执行 1 次。
- 超时后最多额外重试 5 次。
- 每条测试最多执行 6 次。
- 唤醒超时或回复超时均消耗一次重试机会。
- 所有尝试均保留记录，不能用最后一次结果覆盖之前的失败。
- 音频设备断开、文件损坏等执行错误单独记录，不作为设备超时处理。

## 四、音频播放与录音

### 1. 全双工采集

测试期间保持录音连续运行，覆盖：

- 唤醒词播放前的环境声音。
- 唤醒词及设备唤醒回应。
- 测试音频播放。
- 设备回答。
- 回答结束后的短暂静音。

允许分别选择输入和输出设备。测试开始前进行设备可用性检查，确认可以同时播放和录音。

### 2. 排除电脑播放声音的干扰

麦克风会同时收到电脑扬声器和被测音箱的声音，不能把“检测到声音”直接视为音箱回复。

建议采用以下处理链：

```text
麦克风原始音频 + 电脑播放参考音频
                  ↓
             回声消除
                  ↓
             环境噪声抑制
                  ↓
        语音活动检测 / 提示音匹配
```

要求：

- 将正在播放的唤醒词和测试音频作为回声消除的参考信号。
- 对播放结束后的声学残响进行抑制。
- 持续采集，避免通过停录、重启录音规避播放干扰。
- 保留原始录音；处理后的录音可作为额外复核文件。
- 回声消除不可用时，应标记测量模式及可靠性限制，不能静默输出同等可信的结果。

### 3. 首次校准

提供校准入口，完成：

- 环境底噪采集。
- 播放声音泄漏和残响检测。
- 设备实际唤醒回应录制。
- 输入音量及削波检查。
- 播放与采集时间对齐检查。

由于没有明确设备型号，不能硬编码“小米一定回复某句话、百度一定回复某句话”。按设备配置保存实际采集的唤醒回应样本，支持语音和提示音两类模板。

## 五、声音判定规则

### 1. 唤醒成功

在唤醒等待窗口内，检测到符合当前设备配置的唤醒语音或提示音，即判定“检测到唤醒回应”。

建议使用：

- 唤醒语音：语音活动检测结合样本相似度。
- 唤醒提示音：音频模板匹配。
- 多个参考样本：兼容设备不同回应。

匹配失败或超时，应记录为“未检测到唤醒回应”，不要直接宣称设备内部未唤醒。

确认唤醒回应结束后，尽快播放测试音频，避免设备退出等待指令状态。

### 2. 回复成功

测试音频播放后，检测到来自被测设备的有效语音，即判定“检测到语音回复”。

- 不检查回答内容是否正确。
- 错误提示只要是语音，也算有回复。
- 单独的提示音不算语音回复。
- 不强制依赖语音转文字服务。
- 对瞬时噪声设置最短语音长度和连续性要求。
- 语音确认后，将起点回溯至该语音段最初的有效音频帧，避免把确认等待时间计入响应耗时。

纯声音检测不能可靠区分设备语音和附近人员讲话，正式测试应保持安静环境；存在干扰时保留录音并允许人工复核标记。

纯声音方案可以判断“检测到唤醒回应”和“检测到回答”，但无法直接确认设备内部收音状态。报告应区分“未检测到唤醒回应”和“已检测到唤醒回应但未检测到回答”。

## 六、响应耗时计算

统一定义：

```text
响应耗时（ms）
=（设备语音回复起点 − 测试音频实际播放结束时刻）× 1000
```

上式的时间戳单位为秒。

实现要求：

1. 使用单调高精度时钟和音频采样位置建立统一时间基准。
2. 播放结束时刻取最后一个音频采样实际输出对应的时间，不能直接使用“调用播放函数返回”的时间。
3. 输入、输出设备延迟应尽量通过音频后端时间戳和校准补偿。
4. 音频文件尾部静音提供可配置裁剪，并记录是否启用；计时以实际播放内容为准。
5. 内部保存原始精度，只在界面及报告中格式化为两位小数。
6. 缺失耗时显示 `—`，不得填 `0.00 ms`。

示例：

```text
响应耗时：1234.56 ms
```

显示两位小数不代表具有 0.01 ms 的测量准确度。报告应记录采样率、音频帧长度、校准信息及计时方式。

持续监听期间若检测到设备在测试音频结束前开始讲话，单独标记“提前回复/重叠回复”，保留原始时间差，默认不纳入普通响应耗时统计，不能将其截断为零。

## 七、默认配置

以下作为初始值，均允许修改并写入报告。

| 配置项 | 默认值 |
|---|---:|
| 唤醒回应超时 | 5000 ms |
| 语音回复超时 | 15000 ms |
| 超时额外重试次数 | 5 |
| 重试前静音等待 | 2000 ms |
| 最短有效回复语音 | 200 ms |
| 回复结束静音阈值 | 800 ms |
| 单轮最长回复录制时长 | 60000 ms |
| 每条测试重复次数 | 1 |
| 原始录音格式 | WAV |

补充规则：

- 唤醒超时从唤醒词实际播放结束开始计算。
- 回复超时从测试音频实际播放结束开始计算。
- 达到最长录制时间时，若已检测到语音，仍记为有回复，同时标记“录音达到时限”。
- 下一轮开始前检查是否仍有设备语音；持续发声时暂停并提示处理，避免上一轮回答污染下一轮。

## 八、界面功能

新增“音箱黑盒测试”入口，包含：

- 设备类型及自定义设备名称。
- 输入麦克风、输出扬声器选择。
- 唤醒音频选择及试听。
- 唤醒回应校准及样本管理。
- 测试音频目录导入。
- 超时、重试及检测参数配置。
- 开始、停止测试。
- 当前音频、尝试次数、流程状态和检测结果。
- 实时输入音量及录音状态。
- 结果列表、录音回放和报告导出。

停止测试后，应保存已完成结果和当前尝试录音，将当前尝试标记为“用户中止”。

## 九、独立 HTML 报告

### 1. 汇总信息

- 测试任务名称、设备类型、自定义设备名称。
- 测试时间、输入输出设备、检测参数。
- 测试用例数、实际尝试次数、重试次数。
- 首次唤醒回应检出率。
- 首次语音回复成功率。
- 重试后的最终成功率。
- 有效响应耗时的平均值、中位数、P90、P95、最小值和最大值。

明确统计分母：

- 首次唤醒回应检出率：首次检测到唤醒回应的用例数 / 已完成首次尝试的用例数。
- 首次语音回复成功率：首次尝试检测到回复的用例数 / 已完成首次尝试的用例数。
- 最终成功率：任一次尝试成功的用例数 / 已完成用例数。
- 响应耗时汇总：默认取每个用例首次成功且无重叠异常的尝试；另提供全部有效尝试统计。

### 2. 明细信息

每次尝试单独一行，至少包含：

| 字段 | 内容 |
|---|---|
| 用例及音频文件 | 编号、名称、语言 |
| 尝试序号 | 首次或第几次重试 |
| 唤醒结果 | 检测到回应 / 未检测到回应 |
| 回复结果 | 检测到语音 / 回复超时 / 未执行 |
| 响应耗时 | `1234.56 ms` 或 `—` |
| 执行状态 | 成功、超时、执行错误、用户中止等 |
| 异常标记 | 重叠回复、录音达到时限、疑似干扰等 |
| 录音 | 内嵌播放器及文件链接 |

### 3. 文件组织

```text
测试报告目录/
├─ report.html
├─ results.json
├─ config.json
└─ recordings/
   ├─ case_001_attempt_01_raw.wav
   ├─ case_001_attempt_01_processed.wav
   └─ case_001_attempt_02_raw.wav
```

HTML 离线可打开，不依赖外部 CDN。使用相对路径引用录音，整个目录可打包转移。每次尝试结束立即落盘，程序异常退出后仍可根据已有结果重新生成报告。

## 十、验收要求

实现完成后至少验证：

1. 三类设备可独立配置唤醒词和回应样本。
2. 电脑能够同时播放和录音。
3. 唤醒语音及提示音都能作为唤醒确认依据。
4. 电脑播放的测试音频不会直接触发“设备回复成功”。
5. 提示音不会被当作有效语音回复。
6. 唤醒超时、回复超时均最多额外重试 5 次。
7. 每次尝试均有独立记录和原始录音。
8. 时间统一以 `ms` 展示并保留两位小数。
9. 使用已知时间间隔的音频验证计时偏差，并记录验证结果。
10. HTML 汇总与明细一致，离线录音回放正常。
11. 中止、设备断开及程序异常不会丢失已保存结果。
12. 最终使用真实音箱验证整条链路；模拟音频验证不能代替实机验收。
