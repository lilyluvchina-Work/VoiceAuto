# 钉钉群消息通知节点说明

## 一、文档目的

本文档用于说明语音自助交互工具在接入钉钉群消息后，哪些测试流程关键节点需要发送钉钉群通知。

本次通知范围只保留测试流程中的关键状态、关键异常和音箱恢复结果，避免普通流程频繁刷屏。

本次调整要求：所有钉钉通知消息统一携带环境信息，便于群内成员直接判断问题发生在哪个测试环境、服务版本和客户端版本。

---

## 二、钉钉群消息发送节点

说明：下表所有发送节点均需要在消息正文中携带“环境信息”公共字段。

| 序号 | 发送节点 | 消息类型 | 发送原因 |
|---|---|---|---|
| 1 | 开始执行语音测试 | 流程通知 | 标记正式进入语音测试执行阶段 |
| 2 | 测试流程暂停 | 流程通知 | 通知当前测试流程被人工或系统暂停 |
| 3 | 测试流程重置 | 流程通知 | 通知当前测试流程已被重置，需要重新开始 |
| 4 | 音响唤醒连续失败 | 异常告警 | 阻塞语音测试主流程，需要关注 |
| 5 | 音箱重启成功 | 恢复通知 | 通知系统已完成音箱重启，可继续后续测试 |
| 6 | 音箱重启失败 | 异常告警 | 自动恢复失败，需要人工介入 |
| 7 | 测试音频播放失败 | 异常告警 | 当前用例无法正常执行 |
| 8 | 未监听到音响回复 | 异常告警 | 语音交互链路未闭环 |
| 9 | STT识别失败 / 识别结果为空 | 异常告警 | 影响实际回复文本获取 |
| 10 | Langfuse日志拉取失败 | 异常告警 | 影响后续结果分析 |
| 11 | 语音测试完成 | 结果通知 | 通知本轮语音测试已完成 |
| 12 | 测试任务执行失败 / 中断 | 异常告警 | 通知整体流程异常结束 |
| 13 | Speaker监听链路自检结果 | 环境通知 | 通知 ADB、Speaker 设备与 logcat 监听链路当前状态 |

---

## 三、消息公共内容

所有钉钉群通知消息建议统一包含以下公共字段：

| 字段 | 是否必填 | 说明 |
|---|---|---|
| 消息标题 | 是 | 简短说明当前通知事件，例如“语音测试开始”“Langfuse日志拉取失败” |
| 消息等级 | 是 | 对应 INFO / SUCCESS / ERROR / FATAL |
| 测试环境 | 是 | 当前执行或日志拉取环境，例如 UAT / UAT-Local / TEST / PROD |
| 测试批次ID | 建议 | 当前测试 runId；如果尚未生成，可显示 `/` |
| 测试时间 | 建议 | 当前测试开始时间、完成时间或异常发生时间 |
| 触发节点 | 是 | 对应本文档第二节中的发送节点 |
| 环境信息 | 是 | 服务环境、服务版本、APP版本等信息，缺失项显示 `/` |
| 事件详情 | 是 | 当前节点的关键上下文，例如失败原因、用例ID、错误信息、恢复结果 |

### 环境信息字段

环境信息从总结报告或页面当前配置中读取，建议包含以下字段：

| 字段 | 示例 | 说明 |
|---|---|---|
| 测试环境 | UAT (UAT) | 当前 Langfuse / 测试执行环境 |
| Cedar服务环境和版本 | UAT / v1.2.3 | Cedar 后端服务环境与版本 |
| XHome服务环境和版本 | UAT / v2.3.4 | XHome 后端服务环境与版本 |
| Cedar Speaker APP | 1.0.0 | Speaker 端 APP 版本 |
| Cedar TV APP | 1.0.0 | TV 端 APP 版本 |
| 魔童APP | 1.0.0 | 魔童端 APP 版本 |
| 大模型厂商 | Gemini | 模型配置，可选展示 |
| 模型版本 | v2.0 | 模型配置，可选展示 |
| 语音识别配置 | Speaker中文ASR / Speaker中文TTS 等 | 语音链路配置，可选展示 |

字段展示原则：

1. “测试环境”必须展示在消息靠前位置。
2. 服务环境和 APP 版本建议作为“环境信息”块集中展示。
3. 模型配置、语音识别配置在异常排查场景中展示；普通流程通知可只展示服务与 APP 版本。
4. 任何字段没有值时统一显示 `/`，避免消息结构不一致。

### 推荐消息格式

```text
【VoiceAuto】【消息等级】消息标题

测试环境：UAT (UAT)
测试批次ID：20260713-001
触发节点：Langfuse日志拉取失败
发生时间：2026-07-13 17:30:00

环境信息：
- Cedar服务环境和版本：UAT / v1.2.3
- XHome服务环境和版本：UAT / v2.3.4
- Cedar Speaker APP：1.0.0
- Cedar TV APP：1.0.0
- 魔童APP：1.0.0

事件详情：
Langfuse 日志拉取失败，错误信息：接口请求超时。
```

## 四、通知分类说明

### 1. 语音测试关键状态

需要发送消息的节点：

- 开始执行语音测试
- 语音测试完成

说明：用于通知团队本轮语音测试的开始和结束，方便测试负责人及时掌握执行进度。

---

### 2. 测试流程控制状态

需要发送消息的节点：

- 测试流程暂停
- 测试流程重置

说明：当测试流程被人工操作或系统逻辑中断时，需要通知群内成员，避免误以为测试仍在正常执行。

---

### 3. 音箱恢复结果

需要发送消息的节点：

- 音箱重启成功
- 音箱重启失败

说明：音响唤醒连续失败后，如果系统触发音箱重启，需要将重启结果同步到钉钉群。

- 重启成功：说明系统已完成自动恢复，可继续测试。
- 重启失败：说明自动恢复失败，需要人工介入处理。

---

### 4. 主流程阻塞异常

需要发送消息的节点：

- 音响唤醒连续失败
- 测试音频播放失败
- 未监听到音响回复
- STT识别失败 / 识别结果为空
- Langfuse日志拉取失败

说明：以上节点会直接影响语音测试主流程或测试结果完整性，需要及时告警。

---

### 5. 任务异常结束

需要发送消息的节点：

- 测试任务执行失败 / 中断

说明：当测试任务因系统异常、设备异常、接口异常或人工终止导致无法继续执行时，需要发送钉钉群消息通知。

---

### 6. 环境健康检查

需要发送消息的节点：

- Speaker监听链路自检结果

说明：当页面启动、监听配置变化或人工点击“重新自检”后，需要将 ADB、Speaker 在线状态、logcat 可读状态、boot_completed 状态和当前设备 SN 同步到钉钉群，方便测试前确认环境链路是否可用。

---

## 五、不发送消息的节点

以下节点当前不需要发送钉钉群消息：

| 不发送节点 | 说明 |
|---|---|
| 测试任务开始执行 | 不发送，避免与“开始执行语音测试”重复 |
| 测试音频生成完成 | 前置准备流程，不发群消息 |
| 测试音频生成失败 | 当前不纳入钉钉通知范围 |
| 日志与用例匹配失败 | 当前不纳入钉钉通知范围 |
| 测试报告生成成功 | 当前不纳入钉钉通知范围 |
| 测试报告生成失败 | 当前不纳入钉钉通知范围 |

---

## 六、消息发送原则

1. 正常流程只发送关键状态，不发送每一步过程消息。
2. 异常流程只发送会阻塞测试或影响结果的关键异常。
3. 音箱重启结果必须发送，方便测试人员判断是否需要人工介入。
4. 同一异常短时间内重复触发时，建议做消息合并或限频，避免钉钉群刷屏。
5. 所有消息必须携带测试环境；异常告警和任务中断必须携带完整环境信息。
6. 环境信息应从当前测试报告或页面配置中读取，缺失字段使用 `/`，不阻塞消息发送。

---

## 七、推荐消息等级

| 消息类型 | 建议等级 | 说明 |
|---|---|---|
| 流程通知 | INFO | 测试流程开始、暂停、重置等状态变化 |
| 恢复通知 | SUCCESS | 音箱重启成功等自动恢复成功场景 |
| 结果通知 | SUCCESS | 语音测试完成 |
| 异常告警 | ERROR | 唤醒失败、播放失败、STT失败、日志拉取失败等异常 |
| 任务中断 | FATAL | 测试任务执行失败或中断 |

---

## 八、最终通知范围汇总

最终需要接入钉钉群消息的节点如下：

1. 开始执行语音测试
2. 测试流程暂停
3. 测试流程重置
4. 音响唤醒连续失败
5. 音箱重启成功
6. 音箱重启失败
7. 测试音频播放失败
8. 未监听到音响回复
9. STT识别失败 / 识别结果为空
10. Langfuse日志拉取失败
11. 语音测试完成
12. 测试任务执行失败 / 中断
13. Speaker监听链路自检结果

以上 13 类通知均需携带环境信息；其中异常告警、任务中断、音箱重启失败和 Speaker 监听链路自检异常需优先展示完整环境信息和错误详情。

## 九、运行配置说明

前端通过 `dingTalkService` 统一发送钉钉群机器人消息，默认使用同源代理 `/dingtalk-robot` 转发到钉钉开放平台。

环境变量配置如下：

| 变量名 | 是否必填 | 说明 |
|---|---|---|
| `VITE_DINGTALK_ENABLED` | 否 | 是否启用钉钉通知，默认启用；设置为 `false` 时不发送 |
| `VITE_DINGTALK_PROXY_PATH` | 否 | 同源代理路径，默认 `/dingtalk-robot` |
| `VITE_DINGTALK_WEBHOOK` | 是 | 钉钉机器人 Webhook 地址 |
| `VITE_DINGTALK_ACCESS_TOKEN` | 建议 | 钉钉机器人 access_token；Webhook 中已包含时可作为兜底配置 |
| `VITE_DINGTALK_SECRET` | 是 | 钉钉机器人加签密钥，用于生成 `timestamp` 和 `sign` |

开发环境由 Vite 代理 `/dingtalk-robot`，生产环境需要在 Nginx 中配置同名代理路径，避免浏览器跨域导致消息发送失败。

消息发送失败时只在浏览器控制台输出警告，不中断语音测试主流程。
