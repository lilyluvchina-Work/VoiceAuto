# VoiceAuto 多轮对话与智能体评测完成方案

## 一、总体目标

本次迭代围绕 VoiceAuto 语音自动化工具建设两个核心能力：

| 能力 | 目标 |
|---|---|
| 多轮对话 | 实现语音自动化工具与 Speaker 连续交互，一次唤醒后支持多轮上下文对话。 |
| 智能体评测 | 基于多轮对话执行结果，对 Agent 的语音链路、语义能力、任务完成情况进行评测。 |

整体链路：

```text
多轮测试用例
  ↓
唤醒设备
  ↓
执行第 1 轮语音输入
  ↓
获取设备响应
  ↓
判断是否继续对话
  ↓
执行后续多轮输入
  ↓
生成多轮对话记录
  ↓
进入智能体评测
  ↓
输出页面 / Excel / HTML 报告
```

---

## 二、多轮对话完成方案

### 2.1 建设目标

多轮对话能力用于模拟真实用户与 Speaker 的连续交互过程，实现一次唤醒后连续执行多轮测试场景。

| 目标 | 说明 |
|---|---|
| 一次唤醒，多轮对话 | 首轮唤醒后，后续轮次无需重复唤醒。 |
| 支持 10 轮上下文 | 保存用户输入、设备回复、状态、轮次、耗时等信息。 |
| 支持固定用例执行 | 按准备好的多轮测试用例逐轮执行。 |
| 支持语义续聊判断 | 判断当前是否需要继续、结束或重新唤醒。 |
| 支持基础统计 | 输出轮次、耗时、成功率、失败原因等数据。 |

### 2.2 技术架构

```text
多轮测试用例
  ↓
Multi-turn Runner
  ↓
Voice Session Manager
  ↓
Wakeup Controller
  ↓
Audio Input / ASR / Device Response Collector
  ↓
Dialogue State Manager
  ↓
Continue Decision Engine
  ↓
下一轮执行 / 结束会话
  ↓
Multi-turn Report Data
```

### 2.3 核心模块

| 模块 | 职责 |
|---|---|
| Multi-turn Runner | 读取多轮测试用例，按轮次执行输入。 |
| Wakeup Controller | 控制首轮唤醒，判断后续是否需要重新唤醒。 |
| Voice Session Manager | 管理会话、轮次、续聊窗口、超时、中断。 |
| Response Collector | 获取设备回复、ASR 结果、TTS 文本。 |
| Dialogue State Manager | 保存 10 轮上下文和每轮状态。 |
| Continue Decision Engine | 判断是否继续对话、结束、重新唤醒。 |
| Multi-turn Recorder | 记录每轮输入、响应、耗时、状态、失败原因。 |

### 2.4 多轮对话判断逻辑

阶段 1：固定用例驱动。

```text
按照测试用例轮次执行
  ↓
如果还有下一轮，继续输入
  ↓
如果达到最后一轮，结束
```

阶段 2：语义续聊判断。

```text
获取本轮用户输入 + 设备回复 + 上下文
  ↓
判断是否追问 / 补充 / 结束
  ↓
决定下一轮是否继续
```

判断结果建议统一为：

```json
{
  "should_continue": true,
  "need_wakeup": false,
  "dialogue_status": "need_more_info",
  "reason": "设备正在追问房间信息，下一轮无需重新唤醒"
}
```

### 2.5 多轮对话验收标准

| 验收项 | 标准 |
|---|---|
| 多轮执行能力 | 支持至少 10 轮连续对话。 |
| 免唤醒能力 | 首轮唤醒后，后续轮次无需重复唤醒。 |
| 上下文记录 | 每轮输入、回复、状态、耗时记录完整率 100%。 |
| 用例通过率 | 准备好的多轮用例通过率 ≥ 95%。 |
| 语义续聊准确率 | 阶段 2 达到 ≥ 90%。 |
| 报告数据 | 能输出完整多轮执行明细。 |

## 三、智能体评测完成方案

### 3.1 建设目标

智能体评测能力用于在多轮对话执行完成后，根据用户勾选的评测项，自动选择唯一评测方案，并输出评测报告。

| 目标 | 说明 |
|---|---|
| 支持评测项勾选 | 用户可选择唤醒、ASR、TTS、语义、任务等指标。 |
| 自动选择评测方案 | 每次评测只选择一种方案，保证口径一致。 |
| 支持链路类评测 | 评测唤醒、ASR、TTS、完播、response_complete。 |
| 支持语义类评测 | 评测意图、槽位、上下文、回复质量。 |
| 支持报告输出 | 输出页面、Excel、HTML 三种报告。 |

### 3.2 三种评测方式

| 方式 | 名称 | 适用评测项 |
|---|---|---|
| 方式 1 | 当前工具功能逻辑 | 用例通过率、任务完成率、关键词断言、状态流转。 |
| 方式 2 | PlanA：Langfuse / 链路状态评测 | 唤醒、ASR、TTS、TTS 完播、response_complete。 |
| 方式 3 | PlanB：大模型语义评测 | 意图理解、槽位、上下文、语义续聊、回复质量。 |

### 3.3 方案选择规则

每次评测只能选择一种方式，规则如下：

```text
如果勾选项包含唤醒 / ASR / TTS / TTS 完播 / response_complete
  -> 选择方式 2

否则，如果勾选项包含意图 / 槽位 / 上下文 / 语义续聊 / 回复质量
  -> 选择方式 3

否则
  -> 选择方式 1
```

优先级：

```text
方式 2 > 方式 3 > 方式 1
```

原因：

| 优先级 | 原因 |
|---|---|
| 方式 2 优先 | 唤醒、ASR、TTS、完播必须依赖真实链路数据。 |
| 方式 3 其次 | 语义质量需要大模型判断。 |
| 方式 1 兜底 | 基础用例、关键词、状态判断可以由工具本身完成。 |

### 3.4 智能体评测技术架构

```text
多轮对话执行结果
  ↓
评测项配置
  ↓
方案推荐引擎
  ↓
选择唯一评测方案
  ↓
评测数据采集
  ↓
指标计算 / 大模型评分 / 规则断言
  ↓
失败归因
  ↓
页面报告 / Excel 报告 / HTML 报告
```

### 3.5 方式 2 链路评测数据要求

已确认条件：

- Langfuse 有 `response_complete` 字段。
- 可以获取 TTS 文本。
- 工具可以获取每轮输入和设备回复。
- 报告需要支持页面、Excel、HTML。
- 唤醒 / ASR / TTS / 完播埋点实现时检查，如果没有，需要给出明确提示。

方式 2 需要检测的字段：

| 评测项 | 必需字段 |
|---|---|
| 唤醒成功率 | `wake_start`、`wake_success`、`wake_failed`。 |
| ASR 成功率 | `asr_start`、`asr_success`、`asr_failed`、`asr_text`。 |
| TTS 成功率 | `tts_start`、`tts_success`、`tts_failed`、`tts_text`。 |
| TTS 完播率 | `tts_play_start`、`tts_play_complete`、`tts_play_interrupted`。 |
| response_complete | `response_start`、`response_complete`。 |

如果字段缺失，报告中需要提示：

```text
当前勾选了【TTS 完播率】，但未检测到 tts_play_complete 埋点，该指标无法计算，请补充播放完成事件埋点。
```

### 3.6 智能体评测验收标准

| 验收项 | 标准 |
|---|---|
| 评测项勾选 | 支持配置语音链路、语义能力、基础执行类评测项。 |
| 方案推荐 | 根据勾选项自动选择唯一方案，准确率 100%。 |
| 方式 2 评测 | 可计算 response_complete、TTS 文本核查，缺失埋点能提示。 |
| 方式 3 评测 | 输出结构化语义评分和原因。 |
| 报告输出 | 支持页面、Excel、HTML。 |
| 失败归因 | 失败用例归因完整率 ≥ 90%。 |

## 六、最终完成效果

完成后工具具备以下能力：

```text
1. 能执行准备好的多轮测试用例。
2. 能一次唤醒后连续完成多轮对话。
3. 能保存 10 轮上下文。
4. 能判断是否继续对话或结束。
5. 能按用户勾选项选择唯一评测方案。
6. 能评测唤醒、ASR、TTS、完播、语义理解、任务完成等指标。
7. 能输出页面、Excel、HTML 三种报告。
8. 能在埋点缺失时给出明确提示。
```

最终方案总结：

> 先建设多轮对话执行底座，再基于多轮执行结果建设智能体评测能力；评测时由用户勾选指标，系统自动选择唯一评测方案，并输出页面、Excel、HTML 完整报告。
