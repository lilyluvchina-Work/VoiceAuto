# 重要信息脱敏与配置中心设计方案

## 版本说明

- 更新日期：2026-07-24
- 当前落地状态：已完成登录、账号管理、配置中心、PostgreSQL 配置持久化、TAPD / Langfuse / 钉钉配置读取与立即生效。
- 说明：本文保留原方案设计，并补充当前代码已实现的行为，后续以“已落地实现”为准。

## 一、功能目标

为语音自动化测试工具新增重要信息脱敏与配置管理能力，将 Langfuse、TAPD、钉钉机器人、TTS/ASR、数据库、服务器等敏感参数从代码或明文配置文件中剥离，统一在系统中配置、校验和管理。

配置完成后，敏感信息默认隐藏，仅允许具备权限的用户在设置中重新打开配置页面进行编辑和验证；同时支持新增账号、记录登录信息和关键操作记录，提升工具的安全性、可维护性和可追溯性。

## 二、当前问题

| 问题 | 影响 |
|---|---|
| 敏感参数写在代码或配置文件中 | Key 或连接信息变更时需要修改代码，维护成本高 |
| Langfuse、TAPD、钉钉、数据库、服务器等参数明文暴露 | 存在信息泄露风险 |
| 配置缺少统一入口 | 后续新增第三方服务或部署环境时扩展不方便 |
| 不同人员使用同一套配置 | 无法区分操作责任人 |
| 缺少登录和操作记录 | 出现异常后无法追溯是谁修改了配置或执行了任务 |

## 三、整体设计思路

### 1. 登录后校验配置状态

用户登录系统后，后端自动校验当前系统是否已完成必要配置。如果配置未完整，则不允许进入自动化测试工具首页，自动跳转到初始化配置页面。配置完成并验证通过后，才允许正常使用工具。

### 2. 敏感配置统一管理

将 Langfuse、TAPD、钉钉、TTS/ASR、数据库、服务器等参数统一放到配置中心维护。配置中心支持新增配置、编辑配置、查看配置状态、测试连接、启用或禁用配置、脱敏展示和配置修改记录。

### 3. 敏感信息加密存储

API Key、Token、Secret、Webhook、AppKey、AppSecret、数据库密码、SSH 密码或私钥等敏感字段，后端入库前进行加密处理。数据库中不保存明文敏感信息，页面展示时统一脱敏。

```text
原始值：sk-abc123456789xyz
展示值：sk-abc****xyz
```

### 4. 设置入口重新编辑

配置完成后，敏感参数默认隐藏。管理员或测试负责人可在系统设置中重新进入配置页面，点击编辑后重新输入完整参数、测试连接并保存配置。

### 5. 支持新增账号与记录登录信息

系统支持新增账号，并记录用户名、登录账号、角色、状态、创建时间、最近登录时间等信息。同时记录登录 IP、登录结果、关键操作类型、操作对象、操作时间和操作结果。

## 三、已落地实现补充

### 1. 登录与权限

| 能力 | 实现 |
|---|---|
| 登录 | `POST /api/auth/login` |
| 登录态校验 | `GET /api/auth/profile` |
| 退出 | `POST /api/auth/logout` |
| 新增账号 | `POST /api/users` |
| 登录态 | HttpOnly Cookie：`voiceauto_session` |

当前角色：

- `admin`：用户管理、配置查看/修改、测试执行、报告查看等权限。
- `test_lead`：测试执行、报告生成和查看权限。

### 2. 配置中心持久化

配置中心数据已从浏览器本地存储迁移到 PostgreSQL。

| 接口 | 说明 |
|---|---|
| `GET /api/configs` | 查询全部已保存配置 |
| `GET /api/configs/:type` | 查询单类配置 |
| `PUT /api/configs/:type` | 保存单类配置 |

配置表为 `app_config`，应用访问配置接口时会自动创建。

| 字段 | 说明 |
|---|---|
| `config_type` | 配置类型，如 `tapd`、`langfuse`、`dingtalk` |
| `payload` | 配置 JSON |
| `updated_by` | 最近修改人 |
| `created_at` | 创建时间 |
| `updated_at` | 最近更新时间 |
| `version` | 配置版本 |

### 3. 默认配置与入库

默认钉钉、TAPD、Langfuse 参数集中维护在：

```text
src/config/sensitiveDefaults.js
```

部署后可执行以下命令将默认配置写入 PostgreSQL：

```bash
node scripts/seedDefaultConfigs.js
```

Docker 容器中执行：

```bash
docker exec voiceauto-web-api-test node scripts/seedDefaultConfigs.js
```

文档中不重复写完整 Key、Token、Secret；修改真实参数应优先在配置中心保存。

### 4. TAPD 参数来源

TAPD 导入测试用例时，参数从配置中心/数据库配置读取。

| 页面展示 | 字段 |
|---|---|
| 应用 ID | `apiUser` |
| 应用密钥 | `apiPassword` |
| 公司 ID | `companyId` |
| 项目 ID | `workspaceId` |
| 目录调试开关 | `debugDirectoryMapping` |

TAPD 导入向导不再读取旧的 `voiceauto_tapd_config_v1`，也不在导入窗口中临时保存参数。项目 ID 由配置中心控制，导入窗口只读展示。

### 5. Langfuse 参数来源

Langfuse 支持多环境配置，环境列表从配置中心/数据库配置生成。每个环境包含：

| 参数 | 字段 |
|---|---|
| 环境 Key | `envKey` |
| 环境名称 | `label` |
| 代理路径 | `proxyBase` |
| Base URL | `baseUrl` |
| Public Key | `publicKey` |
| Secret Key | `secretKey` |
| 启用状态 | `enabled` |

语音测试页“日志环境”下拉和 Langfuse 日志页环境按钮都从启用环境列表生成，不再写死 `UAT` 或固定环境。

### 6. 钉钉参数来源

钉钉群消息参数从配置中心/数据库配置读取。

| 参数 | 字段 |
|---|---|
| Webhook | `webhook` |
| 加签 Secret | `secret` |
| 代理路径 | `proxyPath` |
| 启用状态 | `enabled` |

通知发送服务优先读取配置中心的运行时配置，不再依赖 `VITE_DINGTALK_*` 作为主要来源。

### 5. 数据库配置

数据库配置用于连接和维护自动化测试工具的数据存储能力，包括用户信息、配置数据、测试任务、测试报告、登录记录和操作日志等。

| 参数 | 是否敏感 | 说明 |
|---|---|---|
| 数据库类型 | 否 | MySQL / PostgreSQL 等 |
| 数据库地址 | 是 | 数据库服务器 IP 或域名 |
| 数据库端口 | 否 | 默认 MySQL 为 3306 |
| 数据库名称 | 是 | 自动化工具使用的数据库名称 |

| 数据保留周期 | 否 | 测试报告、日志、登录记录保留时间 |


## 八、使用流程

### 1. 首次使用流程

```text
用户登录
  ↓
系统检查数据库、服务器、Langfuse、TAPD 等必要配置
  ↓
配置不完整 → 跳转初始化配置页面
  ↓
填写数据库 / 服务器 / Langfuse / TAPD / 钉钉等配置
  ↓
测试连接
  ↓
连接成功
  ↓
保存配置并脱敏展示
  ↓
进入自动化测试工具首页
```

### 2. 后续使用流程

```text
用户登录
  ↓
系统校验配置完整性
  ↓
配置正常
  ↓
进入自动化测试工具首页
  ↓
正常创建任务 / 执行测试 / 查看报告
```

### 3. 配置修改流程

```text
管理员或测试负责人进入设置
  ↓
打开配置中心
  ↓
选择数据库配置、服务器配置或第三方服务配置
  ↓
点击编辑
  ↓
重新输入敏感参数
  ↓
测试连接
  ↓
保存配置
  ↓
记录操作日志
```

## 九、技术实现方案

### 1. 前端实现

前端需要新增登录页面、初始化配置页面、配置中心页面、账号管理页面、操作日志页面和登录记录页面。敏感字段默认展示为“********”，点击编辑时清空输入框，要求重新输入完整值，保存成功后重新脱敏展示。不建议提供“查看明文”功能，避免敏感信息二次暴露。

### 2. 后端实现

| 接口 | 功能 |
|---|---|
| 登录接口 | 用户登录认证 |
| 配置状态接口 | 判断系统配置是否完整 |
| 配置保存接口 | 保存加密后的配置 |
| 配置查询接口 | 查询脱敏后的配置 |
| 配置测试接口 | 校验 Langfuse / TAPD / 钉钉 / 数据库 / 服务器等是否可用 |
| 账号管理接口 | 新增、编辑、禁用账号 |
| 登录日志接口 | 查询登录记录 |
| 操作日志接口 | 查询配置修改和任务操作记录 |

### 3. 加密方案

| 对象 | 处理方式 |
|---|---|
| 用户密码 | 使用 BCrypt 或 Argon2 加密，不可逆存储 |
| API Key / Token / Secret | 使用 AES 加密后存储，用于后端调用第三方服务 |
| 数据库密码 / SSH 密码 / 私钥 | 使用 AES 加密或服务器环境变量管理 |
| 加密密钥 | 放在服务器环境变量中，不写入代码仓库 |
| 日志输出 | 禁止打印完整 API Key、Token、Secret、Webhook、数据库密码、SSH 凭据 |

## 十二、异常处理

| 场景 | 处理方式 |
|---|---|
| 首次登录未完成配置 | 跳转初始化配置页面 |

| 配置被修改 | 记录操作日志 |
| 登录失败 | 记录失败原因和登录 IP |

## 十三、落地优先级

| 阶段 | 优先完成内容 |
|---|---|
| 第一阶段：基础可用 | 登录功能、账号管理、配置中心、Langfuse / TAPD / 钉钉 / 数据库 / 服务器配置管理、敏感信息加密存储、脱敏展示、配置完整性校验 |
| 第二阶段：安全增强 | 操作日志、登录日志、权限控制、配置测试连接、配置启用 / 禁用、配置修改记录 |
| 第三阶段：扩展能力 | TTS / ASR 配置、大模型评测配置、邮件服务配置、其他测试工具配置、多环境配置管理 |

## 十四、预期效果

1. 敏感信息不再写死在代码中。
2. Langfuse、TAPD、钉钉、TTS/ASR、数据库、服务器等配置可统一维护。
3. 配置变更无需重新修改和部署代码。
4. 页面默认隐藏敏感信息，降低泄露风险。
5. 支持新增账号和角色管理。
6. 支持记录登录信息和关键操作信息。
7. 出现问题时可以追溯是谁登录、谁修改了配置、谁执行了任务。
8. 数据库连接、服务器部署、日志路径、音频设备、ADB 配置可追溯。
9. 出现环境问题时，可以快速定位是数据库、服务器、第三方平台还是设备配置异常。
10. 后续新增第三方服务时，可以快速接入配置中心。
11. 提升自动化测试工具的安全性、可维护性和平台化能力。
