# VoiceAuto 用户使用指引

## 适用对象

- 测试工程师
- 客户体验人员
- 业务验收人员

本指引只讲“怎么操作”，不涉及技术细节。

## 1. 先了解主要页面

进入系统后，顶部有以下页面入口：

- 语音测试：执行测试任务的主页面。
- 测试过程记录：查看每一步测试进展。
- Langfuse 日志：查看日志并下载结果。
- 测试用例管理：导入、整理和维护测试用例。
- 配置中心：维护 TAPD、Langfuse、钉钉、TTS、服务器等配置。
- 总结报告：查看和导出本次测试总结。

系统需要先登录才能使用。管理员账号可进入配置中心和账号管理；测试负责人主要用于执行测试和查看报告。

## 1.1 配置中心怎么用

配置中心的数据保存到数据库，刷新页面或更换浏览器后仍会从数据库读取。

当前重点配置：

- TAPD 配置：应用 ID、应用密钥、项目ID、公司ID。
- Langfuse 配置：按环境分块维护，例如 Test-Local、Prod-Local、UAT-Local、Test、Prod、UAT。
- 钉钉群消息参数：Webhook、加签 Secret。
- 豆包 TTS 配置：APP ID、Access Token、Secret Key、Resource ID。当前标准资源为 `seed-tts-2.0`。

保存后影响：

- TAPD 导入向导会读取最新 TAPD 配置。
- 语音测试页“日志环境”会读取最新 Langfuse 环境列表。
- Langfuse 日志页环境按钮会读取最新 Langfuse 环境列表。
- 钉钉通知会读取最新钉钉配置。

## 2. 一次完整测试怎么做

按下面 6 步即可完成一次标准测试。

### 第 1 步：准备测试用例

先进入“导入测试音频”区域或“测试用例管理”页面，按来源准备测试内容：

- 音频文件导入：在“导入测试音频”页第一个入口选择 mp3、wav、ogg、m4a 文件；导入后会直接显示在当前页面。
- 文本文件导入：在“导入测试音频”页选择 `.txt` 文件，每行作为一条文本用例。
- 手动输入：适合少量临时文本用例。
- 从 TAPD 接口导入：在“测试用例管理”页点击右上角“TAPD 接口导入”，参数从配置中心读取，不在导入窗口中临时维护。

检查要点：

- 用例内容是否完整
- 模块分类是否正确
- 没有明显重复或无效语句
- 文本导入用例会在“测试用例管理”页置顶显示，并标记为“文本导入”。
- TAPD 用例会标记为“TAPD”，与文本导入用例区分显示。

### 第 2 步：生成可测试音频

在“测试用例管理”中，为需要执行的用例生成测试音频。

建议：

- 先按模块生成并检查结果
- 重点用例可先单条生成确认

### 第 3 步：设置测试参数

进入“语音测试”页面，设置以下内容：

- 唤醒词
- 音色和语速。当前音色下拉只展示 `seed-tts-2.0` Resource ID 下已验证可播放的音色。
- 音量
- 循环次数
- 测试模块
- 测试结束后要自动拉取的 Langfuse 日志环境
- 是否开启自主监测

建议：

- 首次使用先用较少循环次数
- 批量回归前先试跑一小批
- 如果需要自动生成总结报告，先确认“自动拉取 Langfuse 日志”已开启，并选择正确日志环境
- 日志环境选项来自配置中心的 Langfuse 环境配置。

当前语音测试页的主要区域是：

- 播放控制台 / 唤醒词配置
  - 之前：播放控制台和唤醒词配置是两个独立卡片。
  - 现在：唤醒词文本、唤醒后延迟、唤醒间延迟和试听入口已合并到播放控制台。
- 测试音频列表
  - 之前：文本内容按单行截断，功能模块、来源和时长占用独立固定列。
  - 现在：测试音频文本完整多行显示，功能模块、来源和时长以标签形式显示在文本上方。

如果需要系统自动判断 Speaker 是否真的完成“唤醒、识别、回复”，在播放控制台开启以下配置：

- 自主监测唤醒是否成功
  - 用于判断 Speaker 是否被唤醒。
  - 依赖 ADB 日志中的唤醒成功标识。
- 自主监测测试音频与 ASR 输入
  - 用于判断测试音频是否被 Speaker 识别。
  - 页面会记录实际 ASR 文本和相似度。
- 自主监测 Speaker 响应内容
  - 用于判断 Speaker 是否有回复、是否播报结束。
  - 页面会录制 Speaker 播报音频，并显示 Speaker 播报音频收录文本。

开启前检查：

- Speaker 设备已连接并在线。
- ADB Bridge 地址正确，默认是 `http://127.0.0.1:17321`。
- 页面顶部“Speaker 监听链路自检”为正常。
- 浏览器已授权麦克风权限。
- 外部麦克风能采集到 Speaker 播放声音。

如果自检异常，可以点击“重新自检”或“一键恢复”。

### 第 4 步：开始执行

在播放控制台顶部“测试过程”面板下方点击“开始测试”。

测试过程中你可以：

- 暂停
- 继续
- 停止
- 重置

页面会实时显示：

- 当前状态
- 当前阶段
- 当前文本
- 当前执行到第几条
- 总体进度、完成率、已用时间、预计剩余

开启自主监测后，流程会变为事件驱动：

- 唤醒成功后立即播放测试音频。
- 测试音频播放完成后立即采集 Speaker 响应。
- Speaker 播报结束并等待冷却后，再进入下一条用例。

### 第 5 步：查看过程记录

进入“测试过程记录”，可查看：

- 每条用例是否成功
- 失败出现在哪一步
- 当前批次执行情况
- 唤醒状态、ASR 状态、Speaker 播报音频收录状态
- Speaker 播报录音，可在线播放或下载
- Speaker 播报音频收录文本、文本相似度、录音时长、采样率
- 录音结束原因和是否疑似截断

页面顶部会汇总：

- 唤醒成功多少次、失败多少次
- ASR 成功多少次、失败多少次
- Speaker 播报音频收录成功多少次、失败多少次

最终结论判定口径：

- 之前：过程记录中单独展示“提取 Speaker 回复文本”，最终结论可能受 Speaker 回复文本提取结果影响。
- 现在：过程记录取消单独“提取 Speaker 回复文本”步骤，文本合并显示在“Speaker 播报音频收录”中；播放唤醒音频、监听唤醒结果、播放测试音频、监听 ASR 输入、Speaker 播报音频收录这五项都成功时，最终结论判定为成功。

### 第 6 步：导出与留档

测试完成后可导出结果，用于共享和归档。

测试过程记录支持导出 Excel：

- 之前：测试过程记录主要支持页面查看和复制 JSON。
- 现在：点击“导出 Excel”可得到包含“概览”和“具体数据”两个 Sheet 的文件；具体数据会按用例展开，并合并相同用例级单元格。

建议保留：

- 本次测试结果
- 异常用例清单
- Speaker 播报录音
- 关键日志文件
- 总结报告（Markdown / HTML / Excel）

错误日志也可以统一汇总：

- 之前：错误信息分散在多个日志文件里，需要逐个搜索。
- 现在：运行 `npm run logs:errors` 会生成 `logs/error-summary.log`，集中查看错误/异常相关日志。

## 3. Langfuse 日志怎么用

如果需要日志排查，请在“Langfuse 日志”页面操作：

1. 选择环境
2. 选择时间范围
3. 点击“获取日志”
4. 在“数据预览”中按需选择 familyid / deviceid
5. 查看结果并导出，或点击“生成报告”

中途支持暂停、继续或终止。终止后，已获取的数据会保留。

如果在语音测试页开启了“自动拉取 Langfuse 日志”，测试完成后页面会先停留 2 分钟，再自动跳转到 Langfuse 日志页并拉取所选环境日志。

环境说明：

- Langfuse 日志页只展示配置中心中启用的环境。
- 默认环境取配置列表中的第一个启用环境。
- 如环境缺失或 Key 失效，请先到配置中心更新并保存。

## 4. 总结报告怎么用

生成报告后，进入“总结报告”页面查看：

- 基础信息和功能模块统计为只读，不需要手动修改。
- 提测参数可以直接编辑，也可以导入 `.xlsx/.xls/.csv/.txt` 参数文件。
- 报告表格只统计本次实际执行音频，未执行的导入用例不会计入本次报告。
- 报告正文可刷新为标准 Markdown 格式，并支持导出 Markdown、HTML、Excel。

## 5. 常见使用场景

### 场景 A：日常冒烟测试

- 选择核心模块
- 每个模块执行少量关键用例
- 快速确认主流程可用

### 场景 B：版本回归测试

- 按模块分批执行
- 提高循环次数
- 导出完整结果用于对比

### 场景 C：问题复现

- 仅保留相关模块和用例
- 缩小测试范围反复验证
- 配合日志页面定位问题

### 场景 D：验证 Speaker 是否完整播报

- 开启“自主监测 Speaker 响应内容”
- 选择正确外部麦克风
- 适当调高最大等待/录制时长
- 长文本用例建议使用 120s 最大录制和 3500ms 以上长文本静音结束
- 执行后在“测试过程记录”中播放 TTS 录音并查看是否疑似截断

## 6. 常见问题处理

### 6.1 页面无法访问

- 刷新页面后重试
- 确认使用了正确访问地址
- 若是局域网访问，确认设备在同一网络

### 6.2 测试无法开始

- 确认已准备测试用例
- 确认已生成测试音频
- 先减少用例数量再尝试

### 6.3 结果和预期不一致

- 检查用例文本是否有歧义
- 检查参数设置是否变更
- 复测同一批次，确认是否稳定复现

### 6.4 日志获取结果过少

- 适当扩大时间范围
- 切换到正确环境后重试
- 分时段多次获取并合并查看
- 自动拉取场景下，确认测试完成后已等待 2 分钟再进入日志拉取

### 6.5 Speaker 监听链路异常

- 点击播放控制台中的“重新自检”。
- 如果仍异常，点击“一键恢复”。
- 确认 `adb devices` 能看到设备，且状态不是 `offline` 或 `unauthorized`。
- 必要时重新插拔设备或重新授权 USB 调试。

### 6.6 ASR 文本为空或不准确

- 确认已开启“自主监测测试音频与 ASR 输入”。
- 确认 ADB 日志中能看到 `asr_status` 或 `input_text`。
- 检查 ASR 文本提取正则是否覆盖当前日志格式。
- 如果只是文本相似度低，先核对测试音频文本是否和实际播放内容一致。

### 6.7 TTS 录音为空或过短

- 确认已开启“自主监测 Speaker 响应内容”。
- 确认浏览器麦克风权限已授权。
- 确认选择的外部麦克风能采集到 Speaker 声音。
- 调低噪声阈值或提高 Speaker 音量。
- 长回复场景下调大“最大等待/录制”“长文本静音结束”“最短保护时长”。
- 在过程记录中查看“结束原因”和“疑似截断”判断。

## 7. 使用建议（重要）

- 先小批量试跑，再做全量测试。
- 关键模块优先，边测边看过程记录。
- 开启自主监测时，先确认 Speaker 监听链路自检正常。
- 长文本 TTS 用例建议单独试跑，确认录音完整后再批量执行。
- 异常用例及时单独标记，便于复查。
- 每轮测试结束都导出结果，避免遗漏。
